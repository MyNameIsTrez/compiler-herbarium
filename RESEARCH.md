# Research dump

A running list of links to compiler designs, papers, posts and repos that are relevant to this repo. It has three tables:

1. Leads that already have an entry in this repo.
2. Leads that do not have an entry yet, and still need to be investigated.
3. Leads that were considered and declined.

When a lead gets an entry, move its row from the second table to the first. New leads usually arrive as issues, see [CONTRIBUTING.md](CONTRIBUTING.md).

The "Read" column says whether the lead has been read in enough depth to rely on, not just listed. ✅ means read, ❌ means not read yet.

## Considered and declined

These do not pass "What earns an entry" in the [README](README.md).

| Lead | Why declined |
|------|--------------|
| A language that only lowers to LLVM IR | The back end would repeat `distilled/clang`. The front end, a language-specific lowering, is the part this repo leaves out. A design whose middle IR is the interesting part, such as MIR in rustc, is judged on that IR instead. |
| Bantam | A Pratt parser demo. The repo leaves out the parser. |
| Brainfuck compilers | Eight commands map nearly one-to-one onto machine code. There is no IR, scoping or type system, so the compiler is a table. `original/naive` already shows expanding code with no IR in between. |
| Finch | A prototype-based object model on a register bytecode with upvalues, in C++. Only the README and the opcode list in `Block.h` were checked. The register bytecode and upvalues repeat `distilled/puc-lua` and Bulfinch, and prototypes are an object model, not a compiler design. Worth a second look if prototype dispatch becomes a lead. |
| Jasic | A BASIC interpreter in one Java file. BASIC's statements and `goto` have trivial semantics. Only the file listing and README were checked. |
| `mark-sweep` and `lisp2-gc` | Garbage collectors (mark-sweep, and LISP2 mark-compact), not compilers. A collector is runtime design, which this repo leaves out. A compiler entry that needs one can include the part it uses, as clox's `memory.c` would. |
| Vigil | A 105-line Python script that rewrites `implore` and `swear` lines with regular expressions into calls of helper functions and then `exec`s the result in Python. It is a thin layer over an existing back end. |
