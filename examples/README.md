# Examples

The programs every entry must compile (or interpret) correctly. Each directory is one task, in the spirit of a Rosetta Code task:

- `program.lua` is the language-neutral definition of the task, written in the small subset of Lua that this repo uses.
- `expected.txt` is the exact stdout the program must produce. It was generated by running `program.lua` with real Lua 5.4, so the expected output does not rest on anyone's reading of the program.

Entries do not parse `program.lua`. Each entry hardcodes the program in its own IR, inside its `main.c`, and is run as `./a.out <example>`.

| Example | What it adds | Output |
|---------|--------------|--------|
| `hello` | Printing a string | `Hello, world!` |
| `arithmetic` | Integer `+`, `-` and `*` with constants | `14` |
| `branch` | Locals, a comparison and an `if` with an `else` | `5` |
| `loop` | A `while` loop that updates locals | `55` |
| `call` | A recursive function with an argument and a return value | `120` |

## The subset

The programs only use integers, `local` variables, `+`, `-`, `*`, `<`, `if`, `while`, local functions with one argument, `return` and `print`. `print` is only called with a string literal or a non-negative integer, so entries never need to print negative numbers.

New examples extend the ladder and must be added to every entry. They must keep to the same subset, or the subset grows with them.

Superoptimizers run on [`kernels/`](../kernels/) instead of these examples.
