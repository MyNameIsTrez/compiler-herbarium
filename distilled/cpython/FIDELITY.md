# Fidelity: cpython

Real design being mimicked: [python/cpython](https://github.com/python/cpython), the bytecode compiler and the eval loop, at commit `9d05428b29508873fb26832eea5d17e0e8de60df` (version 3.16.0a1+dev, a shallow clone of the default branch).

Reference material used:

- Source: the repository above, built with `CFLAGS=-O0 ./configure && make python`.
- Read in depth, all in `Python/`: `compile.c` (`compiler_mod`, `_PyCompile_EnterScope`, `_PyCompile_OptimizeAndAssemble`, `optimize_and_assemble_code_unit`); `codegen.c` (`codegen_enter_scope`, `codegen_function`, `codegen_if`, `codegen_while`, `codegen_jump_if`, `codegen_return`, `codegen_call`, `codegen_addcompare`, the binary operation, assignment and expression statement cases, `codegen_nameop`, `_PyCodegen_AddReturnAtEnd`); `flowgraph.c` (`_PyCfg_FromInstructionSequence`, `_PyCfg_OptimizeCodeUnit`, `optimize_cfg`, `basicblock_inline_small_or_no_lineno_blocks`, `remove_unreachable`, `maybe_instr_make_load_smallint`, `maybe_instr_make_load_common_const`, `basicblock_optimize_load_const`, `optimize_basic_block` for the cases used here, `fold_const_binop`, `remove_unused_consts`, `calculate_stackdepth`, `normalize_jumps`, `optimize_load_fast`, `insert_superinstructions`); `assemble.c` (`write_instr`, `resolve_jump_offsets`, `resolve_unconditional_jumps`, `assemble_emit_instr`).
- Not read: `symtable.c` (the symbol table stage is written from the behavior seen in `dis` output and in `codegen_nameop`, not from its source), `ceval.c`, `bytecodes.c` and `generated_cases.c.h` (the eval loop follows the stack layout that the compiler's output implies), `specialize.c`, the line table and exception table code in `assemble.c`, `get_const_loading_instrs`, the parser and tokenizer, and the JIT.
- The real interpreter was built and `dis.dis` and `co_code` were compared with the entry's output. See the comparison at the end.

## Deliberate deviations

- `optimize_load_fast` is reduced to its outcome for these inputs. The real pass simulates the stack and keeps `LOAD_FAST` when a value could outlive the local it came from (a store to the local while the value is on the stack, or a value left on the stack at the end of a block). None of the examples stores to a local of a function or leaves a value across blocks, so every `LOAD_FAST` becomes `LOAD_FAST_BORROW`, and the code stops with an error if a block starts with a value on the stack.
- The fold of constants looks for two `LOAD_SMALL_INT`s directly before the operation. The real `get_const_loading_instrs` was not read and may also skip NOPs between them.
- Where the real code tests a condition that the examples never make false, such as a `LOAD_GLOBAL` that is not followed by `PUSH_NULL`, this entry stops with an error instead, so that every line and branch is covered.
- There are no locations, so none of the line-number rules that decide whether a block is inlined are present. Only the "small exit block" rule is. The real function also inlines a block that has no line number and no fallthrough, which none of the examples needs.
- The Lua examples become Python programs by dropping `local`, and `local function` becomes `def`, so every name at module level is a global and gets `LOAD_NAME` and `STORE_NAME`. The functions use `LOAD_GLOBAL` for `fact`.

## Comparison with the real tool

Command: `python -I -S` on the Python version of each example, with `dis.dis(code, show_caches=False, adaptive=False)` and `co_code`, `co_stacksize`, `co_names` and `co_consts` of the code objects, from the commit above.

- Matches: for all five examples the final instructions, the argument of every instruction, the cache entries, and therefore the whole `co_code` byte string are identical, for the module and for `fact`. `co_stacksize` and `co_names` also agree, and so do `co_consts`, including the kept slot 0 (`(2,)` for `fact`, `(0,)` for the loop, `(3,)` for the branch).
- Differs: no line table and no exception table, so the code object is not complete.
- Not compared: the intermediate forms. The real compiler has no switch to print the sequence, the blocks or the optimizer's passes. They are built from the source that was read.
