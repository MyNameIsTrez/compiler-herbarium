# Fidelity: gcc

Real design being mimicked: [GCC](https://gcc.gnu.org/), the GNU Compiler Collection, from a shallow clone of the default branch of [gcc-mirror/gcc](https://github.com/gcc-mirror/gcc) at commit `7a1e872fb30dceffa60af04ee226b1563b757515`, for the x86-64 back end.

Reference material used:

- Source: the repository above, with only `gcc/*.cc`, `gcc/*.h`, `gcc/*.def`, `gcc/*.md` and `gcc/config/i386/i386.md` and `i386-expand.cc` checked out.
- Read in depth: `gimplify.cc` (`gimplify_cond_expr` with the creation order of `label_true`, `label_false` and `label_cont` and the goto-arm shortcut, `gimplify_return_expr` with the shared return temporary, `gimplify_loop_expr`, `internal_get_tmp_var`, `lookup_tmp_var`, `create_tmp_from_val`); `gimple-low.cc` (`lower_function_body`, `lower_gimple_return`); `tree-cfg.cc` (`make_blocks_1`, `make_cond_expr_edges`, `make_goto_expr_edges`); `tree-into-ssa.cc` (`insert_phi_nodes`, `insert_phi_nodes_for`, `prune_unused_phi_nodes`, `register_new_def`, `get_reaching_def`, `rewrite_stmt`, `rewrite_add_phi_arguments`, `rewrite_dom_walker`); `cfganal.cc` (`compute_dominance_frontiers`, `compute_idf`); `tree-outof-ssa.cc` (`expand_phi_nodes`, `eliminate_phi`, `eliminate_build`, `elim_forward`, `elim_create`); `cfgexpand.cc` (`expand_gimple_cond`, `expand_value_return`, `expand_gimple_stmt`); `combine.cc` (the header comment, `make_more_copies`, `rest_of_handle_combine`, the start of `can_combine_p`, `recog_for_combine_1`, the substitution in `try_combine`, `combine_validate_cost`); `ira.cc` (header) and `ira-color.cc` (`assign_hard_reg` with its cost model, `push_allocnos_to_stack`, `pop_allocnos_from_stack`, `put_allocno_into_bucket`); `final.cc` (`final_scan_insn_1`); `passes.def` for the order of the passes; and the i386.md patterns `*cmp<mode>_1`, `*movsi_internal`, `*jcc`, `jump`, `*call`, `*call_value` and `simple_return_internal`.
- Not read: `dominance.cc`, `fold-const.cc` (so the swap of operands, see the deviations, is copied from the dumps), `function.cc` (prologue and epilogue), `ix86_cc_mode` and the rest of `i386.cc`, `lra*.cc`, `reload1.cc`, `stmt_starts_bb_p`, the internals of `expand_gimple_stmt_1`, the order in which `expand_used_vars` makes pseudos, `i386-expand.cc`, `output_operand` in `final.cc`, the C front end and the whole of the middle-end optimization pipeline between SSA and expand.
- The real compiler (GCC 16.2.1, the installed one) was run with `-fdump-tree-gimple`, `-fdump-tree-ssa`, `-fdump-rtl-expand-slim`, `-fdump-rtl-combine` and `-fdump-rtl-ira` on C versions of the examples. See the comparison at the end.

## Stage mapping

| Stage in this entry | Real stage name | Where it lives in the real source | Kept | Dropped or simplified |
|---------------------|-----------------|-----------------------------------|------|-----------------------|
| `stage_ast` | The C front end, giving GENERIC | `c/` (not read), shape taken from `-fdump-tree-original` | The tree of the function as the front end leaves it: constants folded, `n < 2` as `n <= 1`, `n - 1` as `n + -1`, the call first in `fact (n + -1) * n`, `while` rotated into `goto <cond>; <body>: ...; <cond>: if (c) goto <body>; else goto <exit>;` with the labels numbered exit, cond, body | The parser and the folder. The trees are hand built, with a fixed set of node kinds |
| `stage_gimplify` | `gimplify_function_tree` | `gimplify.cc` | Subexpressions are evaluated left to right into temporaries named `_N`, which are already SSA names. `if` becomes a condition with `label_true` and `label_false`, plus `label_cont` only if the then arm falls through and an else arm exists. All returns write one return temporary `D.nnnn` that is made at the first return. `D` numbers come from one global counter | Everything that is not an assignment, call, `if`, goto or return: no `try`/`finally`, no cleanups, no bind expressions, no gimplification of addresses or loads. The swap of operands to put a temporary last | 
| `stage_lower` | `lower_function_body` | `gimple-low.cc` | `lower_gimple_return`: every return becomes a goto to one label, and the label and one return are appended. A function with no value gets a plain `return;` | Matching the return value of each return to find a shared one (every return here writes the same temporary), and the lowering of binds and nested statements |
| `stage_cfg` | `build_gimple_cfg` | `tree-cfg.cc` | A block starts at a label and after a jump or return. A condition gets its true edge first, then the false edge. A simple goto becomes a plain edge, and the goto and the labels are removed. Blocks start at 2. The dump prints `goto <bb N>;` only when the single successor is not the next block | The entry and exit blocks (0 and 1) and the edges to them, edge flags and probabilities, cleanup (merging blocks, removing forwarders), and the loop structure |
| `stage_ssa` | `pass_build_ssa` | `tree-into-ssa.cc`, `cfganal.cc` | Dominators, dominance frontiers computed as `compute_dominance_frontiers` does, `compute_idf`, PHIs for the variables in order and only where the variable is live on entry, a PHI result named when the PHI is made, renaming along the dominator tree with children in descending block order, default definitions made at the first use and printed with `(D)`, and an artificial return temporary that loses its name | Dominators are found with the iterative bit-set algorithm instead of `dominance.cc`. Liveness is a plain dataflow of the variables instead of the def and use sets of `prune_unused_phi_nodes`. A stack of definitions per variable is a copy of an array per block. Virtual operands, memory and address-taken variables, and every pass between SSA and expand |
| `stage_expand` | `pass_expand`, with `expand_phi_nodes` | `tree-outof-ssa.cc`, `cfgexpand.cc` | The names joined by a PHI share one partition and one pseudo register. A parameter is copied from `di`, a call moves its argument to `di` and the result out of `ax`, a return moves to `ax` and then uses it, a compare is followed by a conditional jump chosen as `expand_gimple_cond` does (jump to the true block if the false block is next, else on the inverse condition to the false block), plus and multiply carry `clobber flags`, and the dump is in the slim RTL format | `eliminate_phi` and the copies it puts on the edges (the partitions of the examples never interfere, so there are none), coalescing by interference, the order in which GCC makes pseudos, modes other than SI, address modes, `lea` selection, and everything else in `expand_gimple_stmt` |
| `stage_combine` | `pass_combine` | `combine.cc` | `make_more_copies` (a new pseudo after each `pseudo = hard register` copy), and the merge of a copy into the insn that uses it, with the cost message of `combine_validate_cost`. A move into a hard register is not combined into, as in the real dump | Combining up to four insns, `can_combine_p` and its many checks, `recog_for_combine` and `undo_all`, the merge of other insn patterns, and notes. Only a copy followed directly by its single use is merged, and the cost check cannot fail for a register copy so it is only printed |
| `stage_ira` | `pass_ira` | `ira-color.cc`, `ira.cc` | A conflict graph where a definition conflicts with everything live except the source of a copy. A call defines every caller-saved register, so a pseudo live across it can only take `bx`. Nodes with fewer neighbors than hard registers are pushed, then popped in reverse. Each takes the cheapest register: copies to a hard register or to a pseudo that already has one are gains, and the first use of the callee-saved `bx` costs. Copies whose two sides got one register are deleted | Costs from register classes and frequencies, live range splitting, coalescing, spilling (the program stops if it is needed), the other registers, `reload` or `lra`, and `postreload` |
| `stage_frame` | `pass_thread_prologue_and_epilogue` | `function.cc` (not read), the rule is from the 16-byte stack rule of the ABI | Push the callee-saved register that is used, and reserve 8 more bytes when the function calls and pushes an even number of registers | Shrink-wrapping (the real compiler pushes `rbx` only on the path that needs it), `rbp` frames, red zones, unwind information |
| `stage_final` | `pass_final` | `final.cc`, `config/i386/i386.md` | Assembly in AT&T syntax from the output template of each insn: `mov`, `cmp`, the conditional jump, `jmp`, `call`, `imul` in two-address form and `add` of a constant as `add` or, with another destination, `lea` | `output_operand`, the other templates and alternatives, `.cfi` directives and alignment, the choice between `sub` and `add` of a negative constant, and the data section directives other than the one string |
| `stage_encode` | The assembler and the linker | GCC runs `as` and `ld` on its text | Not GCC code: this stage encodes the instructions it produced into bytes, records labels and patches the rel32 fields | Not read, since GCC has no counterpart. 8-bit displacements and immediates only, near jumps only, no ELF object, and the runtime (`print_int`, `print_str`) and the string follow the code in the same buffer |
| `stage_export` | The loader | the OS | The code is placed in executable memory and `main` is called | An anonymous `mmap`, `mprotect` and a function pointer. `code.bin` holds the raw bytes |

## Deliberate deviations

- `main` returns nothing, and has no `return 0`. The examples only print, so the real `main` of a C version has `int main (void)` and returns zero. The runtime functions `print_int` and `print_str` are declared like prototypes, and their bytes are part of this file.
- The order of the SSA version numbers matches the real compiler only partly. For `loopn` it matches (`sum_3`, `i_4` in the entry block, then the PHI results `sum_1`, `i_2`), but the real compiler skips some numbers (4, 6 and 7 in `fact`) that this entry does not use, and its default definition `n_5(D)` is numbered after them.
- The temporaries of the gimplifier are numbered from 1 in the order they are made, but the real dumps do not declare them in the `gimple` dump, and neither does this entry. In the `ssa` dump the anonymous names are declared in ascending order, as the real dump does.
- GCC runs many passes between the SSA form and expand at any optimization level (constant propagation, dead code elimination, early inlining and more at `-O1`), which would fold all of these examples. This entry has none of them, so its code is the unoptimized shape. The assembly is nearly what GCC prints at `-O0` for `fact`, without frame pointers.
- The numbers of pseudo registers start at 98 as in the real dump, but the order differs: here a partition gets its pseudo in order of its lowest SSA name, and the real compiler makes them in `expand_used_vars`, which was not read.
- Out of SSA leaves out the copies of `eliminate_phi`. A PHI whose partitions interfere (the lost-copy and swap problems) would give wrong code, and the entry has no example for it.
- Operands of `+` and `*` are swapped so that a temporary comes last, because the real `gimple` dump shows `n * _2`. The rule was not read, and the case that the examples need is all that is implemented. In RTL, `x + -1` is printed as `x-0x1` as the real slim dump does.
- Combine only merges a copy into the next insn, and only into the second operand of an insn. The first-operand case exists in GCC and in the pass here, but no example needs it, so it stops the program instead (`require`).
- The two-address form of `add` and `imul` requires the destination to be one of the operands. GCC expresses this with a matching constraint and fixes it in reload. Here IRA's copy preferences make it so for the examples, and the program stops otherwise.
- The labels in the assembly are numbered from 1 in order of first use, and the jump to the epilogue is the real shape for a function with one return.

## Comparison with the real tool

Commands: `gcc -O0 -c -fdump-tree-gimple -fdump-tree-ssa x.c` and `gcc -O1 -c -fdump-rtl-expand-slim -fdump-rtl-combine -fdump-rtl-ira x.c` with GCC 16.2.1, on C versions of the examples (`fact`, a loop with a parameter bound, and the `if` and `else`), with `void print_int (long)` declared.

- Matches: the shape of the `gimple` dump for `fact` and the loop: the same labels and gotos, the shared return temporary `D.nnnn`, and `_1 = n + -1; _2 = fact (_1); D.nnnn = n * _2;`. The `ssa` dump has the same blocks from 2, the same PHIs at the loop header and at the join, `_9 = 1;` for the constant return, `# _3 = PHI <_9(3), _8(4)>`, the default definition with `(D)` and the descending visit order of the dominator children. For the loop, the first four version numbers equal the real ones. The slim RTL has the same instruction forms: `r101:SI=di:SI`, `flags:CCGC=cmp(...)`, `pc={(flags:CCGC>0)?L4:pc}`, `{r102:SI=r101:SI-0x1;clobber flags:CC;}`, `di:SI=r102:SI`, `ax:SI=call [`fact'] argc:0`, `r99:SI=ax:SI`, `ax:SI=r100:SI` and `use ax:SI`. Combine makes `r104=di` and `r105=ax` in the same way and reports the same merge of the copy into the multiply, with "original costs 4 + 12 = 16, replacement cost 12". IRA puts the parameter, which lives across the call, in `bx`, and the argument and result temporaries in `di` and `ax`.
- Differs: the real dumps annotate edges (`[INV]`, probabilities) and print a condition over three lines. The real compiler folds the constant examples completely, and at `-O1` it shrinks the frame (`rbx` is pushed only on the recursive path, and the blocks are reordered). Output at `-O0` keeps a frame pointer. Version and pseudo numbers differ as listed above, and the real `main` returns an `int`. The comparison is of shapes and stage order, not of text, since only the `gimple` and `ssa` dumps come before the optimizing passes.

## Regenerating expected.txt

Every `examples/<name>/expected.txt` is the output of real Lua 5.4 on that example's `program.lua`, so it does not rest on this entry. Never edit one by hand. From the repository root:

```
for d in distilled/gcc/examples/*/; do lua5.4 "$d/program.lua" > "$d/expected.txt"; done
```

`scripts/check-expected.sh` re-runs the oracle for every entry and fails if a file differs.
